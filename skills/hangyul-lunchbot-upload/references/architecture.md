# Architecture and design notes

Detailed internals of the lunchbot. `SKILL.md` covers running and operating it; read this before changing code or debugging sheet/identity behavior. Paths are relative to the skill directory.

## Architecture

Three core modules are coupled one-way and best-effort: `lunch_bot.py` → `sheet_sync.py`, `menu_fetch.py`. The separate `lunchbot_config.py` module holds every private value — Slack token, channel ID, `SHEET_ID`, `SETTLE_ACCOUNT` — and is intentionally ignored by Git; env vars of the same names override it.

### `lunch_bot.py` — orchestrator

`SlackClient` wraps slack_sdk. Jobs:

- `job_first` — post, seed both emoji, ensure the sheet's date column exists. On the week's **first lunch day** (`_is_first_lunch_day_of_week`: Monday, or the first weekday not blocked by holidays/`NO_LUNCH_WEEKDAYS`) it uploads that week's menu table via `crop_week_menu_image`, falling back to the whole image; on other days `crop_day_menu_image` uploads only tomorrow's weekday column. Menu text OCR is not included in the message.
- `job_final` / `job_midnight` — 22:00 tally reminder; 23:00 confirms at ≥ `MIN_ORDER` people, else posts a cancel and runs `sheet_sync.cancel_day`, which `batch_clear`s every order cell in that date column (so the day drops out of per-person Total/가격 and the settle mentions) and appends `취소` to the date header (`10/20(화) 취소`, still parsed as that date) (`midnight` remains the legacy CLI/function name). Both tally messages list rice and salad orderers separately beside their respective counts.
- `job_sync` — scheduled every five minutes from 20:00 through 22:55 on valid ordering days; runs `_tally` to merge sheet entries and mirror Slack reactions, but posts no Slack message.
- `job_prep` (Fri night) — create next week's tab via `prep_week_tab`, then empty `menu_images/` with `menu_fetch.cleanup_menu_images` (every image there is re-downloaded at the next 20:00); posts nothing to Slack.
- `job_settle` (15:00 on the week's **last working day**) — `_settle_day` walks back from `SETTLE_WEEKDAY` (Fri) past `_is_off` days, so a Chuseok/Hangul-Day Friday settles on the Thursday or Wednesday before it instead; the job itself returns early on any other day (unless `--force`), which is why the cron entry should fire every weekday. `week_orders` → mentions + sheet link, deliberately no amounts; `_resolve_mentions` + `_mention(at_names=True)` (see Identity below). Nobody ordered — including when no tab covers the week — posts `SETTLE_NO_ORDER_MSG_TEMPLATE` instead. Both settle messages carry the week span from `_week_span` (`2026/08/17-2026/08/21`, Mon–Fri via `WEEK_DAY_COUNT`; Mon–Thu with Friday off).
- `_tally` (five-minute syncs, 22:00, and 23:00) — merges sheet entries in *and* mirrors emoji reactions out to the sheet, then registers anyone missing into `명단`.

### `sheet_sync.py` — Google Sheet sync (gspread), structure-adaptive

`_locate` scans **every** tab's header row for a column matching the lunch date in any format (`8/24(월)`, `2026/08/20 (목)`, `8월 24일`; year-less headers match on month/day). `_Layout` then reads that tab's real structure: name column (이름/인원/성명/name, else col A), optional Slack ID column (header matching slack/id/아이디), total column.

- **Human-made tabs are used as-is**: no ID column → rows matched by name, and their Total/가격 cells are never written.
- **Bot tabs** are titled `YYYYMMDD-YYYYMMDD` (that week's Mon–Fri, or Mon–Thu with Friday off), inserted at index 0, structured `인원 | 5 (or 4) date columns | Total | 가격` with no ID column; Total is `=COUNTA(...)` and 가격 is `=Total*8000` (`PRICE_PER_MEAL`), left blank on rows with no name (separator lines). The 인원 column mirrors `명단` top-to-bottom, blank rows and section markers included, and below it come **a blank row, the `Total` summary row, another blank row, and the instruction block** — so the gap above `Total` survives however long the roster gets. The instruction block is carried over from the most recent week tab (`_week_instructions`), or `DEFAULT_INSTRUCTIONS` when the spreadsheet has none yet. Created ahead of time by `prep_week_tab`, or on demand by `_locate(create=True)`.
- **One tab per week.** `_locate(create=True)` first looks for a tab already covering *any* day of that week and, if found, adds the missing date column to it via `_add_date_col` rather than making a second tab — this is the path when a tab built with Friday off (Mon–Thu only, e.g. tabs from before Friday became the default) later needs a Friday column. On a bot tab the column is inserted **before** Total, otherwise the `=COUNTA` range would swallow the Total/가격 cells. Only when no tab covers the week is one prepared; if its exact `YYYYMMDD-YYYYMMDD` title already exists, `_create_week_tab` rebuilds that tab instead of creating a suffixed duplicate. Before rebuilding it snapshots every non-empty person/date order cell and restores it by matching both the person's name (including aliases) and date, so roster row movement does not lose existing orders. The recreated contents include roster rows and per-person Total/가격 formulas. New tabs are duplicated from the previous week's tab for its formatting, so `_align_body_rows` inserts/deletes *rows* (not values) to match the new roster length before the rewrite — that keeps the merged instruction cells lined up with the text written into them. Nothing but column A and the instruction block is written: an API-written `""` in a date cell would be counted by `COUNTA`.
- **Meal labels:** date cells are normalized to exactly `밥`, `샐러드`, or `error`. A dual reaction or an input that cannot be mapped unambiguously becomes `error`; older emoji/text values are normalized when read.
- **Cell ownership**: `sync_reactions` writes only into empty cells and returns the `{uid: mark}` map it wrote (persisted as `synced` in `state.json`). On the next sync it clears a cell for a removed reaction **only if** the cell still holds the bot's own value — anything a person typed is never touched. Clearing uses `batch_clear`, not `""`, because an API-written empty string still counts in `COUNTA`.

### Identity: names, Slack IDs, and mentions

The bot's hardest problem is that the sheet is keyed by human names while Slack is keyed by IDs, and both sides drift. Everything below hangs off `_name_keys`: `지수 (Jisoo)` matches a Slack display name of `지수` or `Jisoo` (full string, outside-parens part, each parenthesized alias; whitespace/case-insensitive).

- **`명단` (roster) tab** is the user-curated master list (`이름 | Slack ID`) and the sole source of week-tab prefill order. `_roster_ws(create=True)` self-heals a missing ID column (`_ensure_roster_id_col`, widening the grid first) — without it `load_roster` skips the tab entirely and every mention degrades to a plain name. Automatic sorting on week-tab creation is currently **disabled** — `sort_roster()` still exists for a manual run (`python -c "import sheet_sync as S; S.sort_roster()"`), but `_create_week_tab` mirrors `명단` in whatever order it is in. `_sorted_roster_rows` sorts ascending *within each section* — a blank row or a `<...>` subtitle (`<Intern list>`) is a boundary that keeps its exact position, so regulars and interns never mix; rows move whole so name↔ID pairing survives, ID-only rows sink to the end of their block, and nothing is written when the order is already correct. Sorting is Unicode-ascending (가나다, Latin names first). New people found on Slack are **inserted at the end of the first (regular) section** rather than appended at the bottom — `add_to_roster` and `sync_reactions` both anchor on `_person_block_end`, the first blank row or `<...>` subtitle, so an auto-registered member never lands in the intern block and everything below (intern section, blank row, `Total`, instructions) shifts down as a whole.
- **Workspace members outside the alarm channel:** `_sync_workspace_roster` reads active human accounts with `users.list` and saves their names and Slack IDs to `명단`, but the channel-member map remains channel-only. It never calls `conversations.invite`, so roster discovery does not invite anyone or make them an alarm recipient. This requires the `users:read` scope; without it the sync is skipped non-fatally.
- **`_channel_members` is the single funnel.** Member map first (`conversations.members` → `save_roster`), else `load_roster` → per-reactor `users.info`. Both branches then run `_refresh_roster_ids` (fill blank IDs: member map, then `users.list`; no API call when the column is full) and `_sync_roster_names`, and merge both results back into the returned map. Every job that touches members therefore attempts to self-heal the roster: 20:00 setup, five-minute syncs, both message tallies, Friday prep, and Friday settle.
- **Renames go by ID, not name.** Slack IDs never change, so `sync_roster_names` takes each roster ID's current display name and rewrites the sheet when the stored name shares no alias key with it — `명단` plus every tab covering this week or later (`_covers_from`), because bot week tabs have no ID column and would otherwise grow a second row under the new name. Past weeks stay as historical record; a new name already owned by another roster row is refused with a warning rather than written.
- **Mentions**: `_mention` emits `<@ID>` for anything ID-shaped. For settle, `_resolve_mentions` first upgrades plain sheet names to IDs (member map → `users.list`, writing finds back into `명단`), then `at_names=True` renders whatever is left as `@이름` — which *looks* like a tag but does not notify. Unmatched names still count in every tally.
- **A Slack ID must never land in a name cell.** With `users:read` denied, `users.info` fails and both `get_channel_members` and `_display_name` fall back to using the ID as the name — which previously flowed straight into the sheet: `sync_roster_names` renamed people to their own ID and propagated it to every current tab, and ID-named "members" got appended as roster rows (bots included, since `is_bot` also can't be read). Two layers guard this now: `_channel_members` discards an all-ID member map and falls back to the roster, and `sheet_sync._is_id_like` blocks ID strings from every name write (`sync_roster_names`, `save_roster`, week-tab prefill, and `add_to_roster`, which converts such an entry into an ID-only row).
- **Automatic identity updates depend on Slack scopes.** Without `users:read`, the bot can receive member IDs but cannot resolve their current display names. Without the applicable membership scope (`channels:read` for a public channel or `groups:read` for a private channel), it cannot discover the channel's members. If either lookup path is unavailable, the bot falls back to the `명단` tab; people missing a valid Slack ID there still count as orders but cannot receive a real Slack notification until the ID is filled in.

### `menu_fetch.py` — caterer menu scraper

Imweb-hosted page that blocks bots, so a browser User-Agent is required. Downloads candidate images and picks the one covering the target date.

**One image can hold several weeks stacked vertically** (e.g. last week above, this week below), which is what made the bot post a stale menu. `header_bands` finds each week's salmon date-header strip and its five weekday columns by colour, and `band_monday` OCRs only that strip: because OCR confuses 1 and 7 (`10/1` → `10/7`), each column votes for `읽은 날짜 − 열 번호` and the modal Monday wins. `_column_mondays` also tries 7→1 swaps of each read (`70/20` → `10/20`) and only counts results that land on an actual Monday — a thin header font once misread four of five columns. `week_band` then returns the strip whose Monday is the target's. Candidate picking tries that first (`has_week_of`), then falls back to the older URL-date → full-image-OCR → largest-file chain. `crop_day_menu_image` crops one weekday column of the matching week, `crop_week_menu_image` crops the whole matching week; both return `None` (caller falls back to the full image) if the week can't be identified — including when easyocr is missing. Menu text is never OCR-read for the message.

## Cross-file mechanics

- **`state.json` is the handoff between jobs.** `job_first` writes the 8PM message `ts` + posting date; `job_sync`/`job_final`/`job_midnight` read it to fetch reactions; `_tally` adds `synced`. `_load_state` accepts only same-day state, so periodic syncs and the 23:00 confirmation run only when that day's 20:00 message succeeded.
- **"Lunch day" is always posting date + 1.** Date labels (`kdate` → `2026/08/20 (목)`) and sheet columns refer to tomorrow.
- **Sheet and menu integrations are deliberately non-fatal**: imported lazily inside try/except in each job, so a missing `service_account.json`, gspread error, scraper breakage, or missing Slack scope only prints a warning — the reminders still post, and tallying still runs with raw Slack IDs standing in for names.
- **Friday lunch is on by default.** `INCLUDE_FRIDAY` (env var or `lunchbot_config.py`, default `True`; `--friday`/`--no-friday` overrides per run) goes through `lunch_bot.set_include_friday`, which sets both `NO_LUNCH_WEEKDAYS` and `sheet_sync.WEEK_DAY_COUNT` (5 vs 4) — always change it through that function so the skip logic and the sheet columns stay consistent.
- **Skip logic** is config constants at the top of `lunch_bot.py`: Korean holidays via the `holidays` package, weekends, `NO_LUNCH_WEEKDAYS` (derived from `INCLUDE_FRIDAY`: empty by default; `{4}` with Friday off → Thursday-evening messages are skipped), and `SETTLE_WEEKDAY = 4` (the settlement reminder's nominal day, moved earlier by `_settle_day` when it is a holiday).
- **Single sources**: `SHEET_ID`, `SETTLE_ACCOUNT` (both loaded from env/`lunchbot_config.py`), `WEEK_DAY_COUNT`, and `_name_keys` live in `sheet_sync.py` and are imported at module level by `lunch_bot.py` — safe because `sheet_sync`'s top-level imports are stdlib plus the optional config module (gspread stays lazily imported inside functions).
